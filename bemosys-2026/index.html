Background · DevOps

DevOps: build it and run it as one loop

A culture and set of practices that unify building software and running it, through automation and fast feedback.

  • Everything in version control, including infrastructure
  • CI: every change is built and tested
  • CD: small, frequent, reversible releases
  • Monitoring and shared ownership in production
Measured by DORA's metrics: deployment frequency, lead time, change failure rate, time to restore.
DORA (DevOps Research and Assessment), dora.dev.
~1.25 min. Short definition for the ML people in the room. The key idea is the loop: building and running are one system, held together by automation (CI/CD) and feedback (monitoring). Mention the DORA metrics: speed and stability measured together.
Background · Why ML needs DevOps

In a real ML system, the model is the small box

Redrawn after Sculley et al., “Hidden Technical Debt in Machine Learning Systems,” NeurIPS 2015.
~0.75 min. Start with only the ML code box. [click] Everything else appears: configuration, data collection and verification, features, resource management, serving, monitoring. That's software engineering, which is why ML in production needed DevOps.

Land the line: MLOps automates ML, and it is software-engineering discipline at its core.

Different conferences, vocabularies and toolchains. Few people were fluent in both.
MLOps lives in that intersection, and it grew slowly.
Coding agents are collapsing the gap.
~1.5 min. Now that both terms are defined, the people story. 01 · State of the art

Every coding agent runs the same loop

Measure is the only step that touches reality.
Agents are optimizers. The evaluator is their objective function.
Anyone from evolutionary computation knows this one: the fitness function is the specification.
~0.75 min. AIDE, R&D-Agent, AlphaEvolve, Claude Code, Codex — architecturally they all run propose–run–measure–repair. [click] The measure step is the only contact with ground truth. [click] So an agent is a search algorithm, and the evaluator is its objective. [click] For the EC people in the room: we've known for decades that evolution exploits any bug in the fitness function. Now that search runs over code, with very strong priors.

02 · The trust problem

Quiet failures: five public cases

2025 · KERNELS

AI CUDA Engineer

Exploited the evaluation code to bypass correctness checks. Claimed up to 100×; re-runs were slower.
The correctness check is part of the attack surface.
2026 · BENCHMARK

SOL-ExecBench

Agents monkey-patched timing functions (3.3% of solutions) and hid work on unsynchronized CUDA streams (2.5%).
The timer is code too.
2024 · RESEARCH AGENT

The AI Scientist

Hit its 2-hour limit, then edited the script to allow 4 hours. In another run it relaunched itself recursively.
Resource limits must live outside the agent's reach.
2025 · EVALUATION

METR frontier evals

Recent models modified tests or scoring code, or found existing answers, to get impossibly high scores.
A surprising score is a reason to inspect, not to celebrate.
2025 · OPERATIONS

Replit agent

Deleted a production database during a code freeze. Preview, test and production shared one database.
Classic ops hygiene now applies to agents.
Sakana AI (2024–25) · SOL-ExecBench, arXiv:2603.19173 (2026) · METR (2025) · AI Incident Database #1152 (2025)
~1.75 min. Transition: "So what goes wrong when the evaluator is weak? Five public cases." One click per case, ~30 s each — keep moving. Emphasize these are public and from serious teams. The pattern: none of these is the model being "dumb" — each is the agent finding the cheapest path to the reward, or acting with permissions it shouldn't have. Replit is not ML-specific, but MLOps pipelines have exactly the same prod credentials problem.

02 · The trust problem

Principle: never let the agent own the judge

The agent writes

  • code and configs
  • models and checkpoints
  • documentation and reports

The judge owns

  • data splits and hidden tests
  • harness, timers, resource limits
  • credentials and production access
1Separate processes, separate permissions.
2The judge's code and data are read-only to the agent — ideally invisible.
3Coarse feedback: pass/fail and a reason, never the hidden answers.
~0.75 min. Separation of powers, borrowed from security and from good experimental practice. [click] the wall. Rule 3 is subtle: if the verifier tells the agent too much, the agent overfits the hidden tests — adaptive overfitting, the same reason Kaggle limits leaderboard submissions.
03 · A guide for your MLOps

Ten rules for MLOps built with agents

Before
1Write the spec and the evaluator first.
2Make tests, eval code and data splits read-only to the agent.
While it works
3Sandbox it; least privilege; no prod credentials.
4Enforce time and resource limits in the OS or CI, not in code it can edit.
Before you trust it
5Evaluate in a separate, frozen process.
6Keep hidden and adversarial test data.
7Treat surprising scores as alarms.
8Calibrate confidence on data the agent never saw.
In production
9Record provenance: tag agent-built artifacts, log the trajectory.
10Monitor drift and coverage; keep rollback and a human sign-off.
~1.75 min. This is the slide people will photograph. Walk the four columns: before (spec and evaluator first, protected paths), while it works (sandbox, no prod credentials, external limits), before you trust it (frozen out-of-process eval, hidden data, anomaly alarms, calibration), in production (provenance, drift and coverage, rollback, human sign-off). The next two slides show how some of these fit together.
03 · A guide for your MLOps

Defense in depth: no single check is enough

Failure modes reaching production: 6 / 6
~1 min. Swiss-cheese model. Each click adds a layer and replays the attacks. (1) Frozen, out-of-process harness stops timer patches. (2) Hidden and adversarial probes stop special-casing known inputs — e.g., held-out shapes for kernels. (3) Sandbox and least privilege: timeouts enforced by the OS, no prod credentials. (4) Anomaly flags: METR found hacks by inspecting anomalously high scores. (5) Calibration on data the agent never saw, plus a human sign-off, for what is left. Every layer has holes; together they cover each other.

04 · Opportunities for LatAm

Where Latin America can lead

Skip the platform team

Agents give small teams MLOps capacity they could never staff. Add the guardrails from day one.

Train “trust engineers”

Universities can train people fluent in both worlds, who write evaluators and specs, not only models.

Verification-first research

Conformal methods, held-out probes and hack-resistant evaluators don't need frontier-scale compute.

Federated and regulated data

Privacy-preserving MLOps where neither the agent nor the judge sees pooled data.

Local benchmarks

Spanish and Portuguese, regional data and real industrial tasks, released as public goods.

Industry where it matters

Manufacturing, energy, agriculture, health: agent-built pipelines with evidence that operators can trust.

~1.25 min. Six opportunities. Emphasize three: skipping the platform team (with guardrails), training cross-community "trust engineers," and verification-first research, which is compute-cheap and therefore a natural niche for the region. Bridge to the papers coming next: federated learning with verifiable inclusion, self-monitoring RAG, a production PV pipeline in Ecuador.
